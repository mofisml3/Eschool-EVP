# 09 — Module: Support & Student Care
## الدعم ورعاية الطلاب

The sixth stop in the narrative arc — the **duty-of-care** chapter. Its purpose is to demonstrate that the program does not leave learners behind: every student is reachable, supported, and — for learners with special needs or accessibility requirements — fully accommodated.

## 2. الأقسام (Page Sections, in render order)

1. **شريط الترحيب** — page hero + period filter.
2. **مؤشرات الدعم الكبرى** — 5 KPI tiles (response time, SLA adherence, tickets handled, first-contact resolution, satisfaction).
3. **اتجاه حجم الاستفسارات** — 12-month tickets volume trend.
4. **توزيع قنوات التواصل** — channel breakdown (chat / email / in-app / phone).
5. **الشمول التعليمي** — inclusion metrics (special-needs learners, schools served, sign-language).
6. **الإتاحة الرقمية** — accessibility features adoption.
7. **الرعاية الإرشادية والأكاديمية** — counseling sessions, follow-ups, parent communication.
8. **الإجراء التالي** — narrative-arc CTA: "الانتقال إلى الأثر الاستراتيجي والقيمة".

## 8. ملاحظات الترحيل (Migration Notes — Static / API / CMS)

| Field | MVP source | Phase 2 destination | Reason |
|-------|------------|---------------------|--------|
| `heroKpis[*].value` | static seed | **API** (helpdesk system) | Live SLA, response, satisfaction |
| `channels[*]` | static | **API** | Aggregation from helpdesk |
| `inclusion.*` | static | **API** (HR/SIS) | Joins enrollment + needs taxonomy |
| `accessibility.captionsCoveragePercent` | static | **API** | Cross-references the videos module — must stay in sync |
| `accessibility.screenReader / highContrast` | static | **internal QA system or CMS** | Updated when accessibility audits complete |
| `wellbeing.*` | static | **API** (counseling + parent comms systems) | Live operational counts |
| `ticketsTrendRef` | static 12-point series | **API** | Time-series store |

**Rule of thumb for this module:**
- All operational counts → **API** (helpdesk + counseling systems).
- Accessibility coverage percentages must be kept in sync with the videos module via a shared computed value, not duplicated independently.
- Inclusion taxonomy (special-needs categories) is policy — kept in shared config.
